# Pitstop v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a single-user, Spanish, mobile-first web app that shows what maintenance is due on my Mazda 6 and keeps a service history with receipts, at $0.

**Architecture:** Next.js 16 App Router, server-first: Server Components read Supabase through a cookie-based server client, and Server Actions mutate. Due-status logic is a pure TypeScript module. Supabase provides Postgres with RLS, Auth and private Storage. Vercel hosts the app and runs a weekly keep-alive cron.

**Tech Stack:** Next.js 16.4.3, React 19.3, Tailwind 4, TypeScript, pnpm, `@supabase/ssr` + `@supabase/supabase-js`, Zod, Vitest, Supabase CLI, Google Fonts (Barlow, Barlow Semi Condensed via `next/font`).

**Spec:** `docs/superpowers/specs/2026-10-26-pitstop-design.md`

## Global Constraints

- Read `node_modules/next/dist/docs/` before writing Next code. Request interception is `proxy.ts` at the project root, **not** `middleware.ts`.
- All UI copy in Spanish. Units: km, MXN (`$1,850.00`, `es-MX`), dates `DD/MM/YYYY`.
- "Today" means the date in **`America/Mexico_City`**, never server UTC.
- $0: Vercel Hobby + Supabase Free only. The service-role key is never used in v1.
- Every table has RLS: `user_id = auth.uid()`.
- Attachments are evidence only: never parsed. Allowed: PDF, JPEG, PNG, HEIC. Max 10 MB per file.
- Due thresholds: Próximo when ≤ 1000 km or ≤ 30 days remain (one config module).
- Design tokens (spec §7): bone `#F5F1EA`, amber `#B86A1B` / `#8A4D10`, brick red for Vencido, sage for OK, warm charcoal in dark mode. Tabular numbers for figures. Animations respect `prefers-reduced-motion`.
- Testing: Vitest unit tests only. No end-to-end tests in v1.

## Review Focus

1. **Back-entering an old service** whose km is lower than the current reading must be accepted. Odometer monotonicity is checked against readings *by date*, not against the latest reading. → Task 3 (schema) + Task 4 (RPC).
2. **Timezone:** at 19:00 in Mexico City on day D, UTC is already D+1. Due dates must use the Mexico City date. → Task 2 (`todayInMexico`).
3. **Month-end:** a service on 31/08 + 6 months is due 28/02 (29/02 in leap years), not 03/03. → Task 2.
4. **HEIC from iPhone** often arrives with an empty or `application/octet-stream` MIME type. Accept it by `.heic`/`.heif` extension. → Task 3.
5. **Double-tap on "Guardar"** must not create two services. Disable the submit while pending (`useFormStatus`). → Task 7.

### Task 2: Due-status logic

**Files:**

**Interfaces:**
- Produces:
  ```ts
  // dates use ISO "YYYY-MM-DD" strings throughout (no Date objects across boundaries)
  export const DUE_SOON_KM = 1000; export const DUE_SOON_DAYS = 30;
  export function todayInMexico(now?: Date): string
  export function addMonthsClamped(isoDate: string, months: number): string
  export function daysBetween(fromIso: string, toIso: string): number

  export type DueStatus = 'vencido' | 'proximo' | 'ok';
  export interface ScheduleItem { id: string; name: string; intervalKm: number | null; intervalMonths: number | null; active: boolean }
  export interface ServiceRecord { date: string; km: number; itemIds: string[] }
  export interface Baseline { date: string; km: number }   // vehicle purchase_date / initial_km
  export interface ItemDue {
    item: ScheduleItem; status: DueStatus;
    last: { date: string; km: number } | null;   // null = never serviced
    nextKm: number | null; nextDate: string | null;
    kmRemaining: number | null; daysRemaining: number | null; // negative when overdue
  }
  export function computeDue(args: { items: ScheduleItem[]; services: ServiceRecord[]; baseline: Baseline; currentKm: number; today: string }): ItemDue[]
  ```
  `computeDue` excludes inactive items and sorts vencido → proximo → ok. Within a status group, items with the least remaining (the smaller of days/30 and km/1000) come first.

- Produces:
  ```ts
  export const odometerSchema: z.ZodType<{ date: string; km: number; confirmJump: boolean }>
  export function checkOdometer(input: { date: string; km: number; confirmJump: boolean },
    neighbors: { before: { date: string; km: number } | null; after: { date: string; km: number } | null }
  ): { ok: true } | { ok: false; field: 'km'; message: string; needsConfirm?: true }
  export const serviceSchema // { date, km, workshop?, totalCostMxn?, notes?, items: { maintenanceItemId: string; costMxn?: number }[] (min 1), confirmJump }
  export const ALLOWED_EXT = ['pdf','jpg','jpeg','png','heic','heif']; export const MAX_BYTES = 10 * 1024 * 1024
  export function checkAttachment(file: { name: string; type: string; size: number }): { ok: true } | { ok: false; message: string }
  export const maintenanceItemSchema // { name, intervalKm: int>0 | null, intervalMonths: int>0 | null, notes?, active } — at least one interval required
  ```
  `neighbors.before` is the latest reading dated on or before `date`, and `after` is the earliest reading dated after it. `checkOdometer` rejects a reading below `before.km` ("El kilometraje no puede ser menor a 45,000 km (lectura del 12/03/2026).") or above `after.km`. If the reading is more than 5000 km above `before.km` and `confirmJump` is false, it returns `needsConfirm`.
